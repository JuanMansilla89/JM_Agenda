# BASE DE CONOCIMIENTO

### Insumo para Propuesta Técnica-Económica

# 1. Contexto General del Proyecto

MINSUR se encuentra evaluando una solución tecnológica orientada a la representación digital de sus plantas de fundición y refinería, con una visión evolutiva hacia un Gemelo Digital Industrial.

La necesidad inicial identificada no se limita a contar con un modelo 3D o BIM visual, sino a desarrollar una plataforma operacional digital que permita navegar la planta, identificar activos, acceder a información técnica asociada y preparar una futura integración con datos operacionales en tiempo real.

El proyecto se encuentra en una fase temprana de definición. El alcance todavía está abierto y puede variar significativamente dependiendo del nivel de detalle BIM requerido, la precisión esperada, la cobertura de planta, la disponibilidad de información, la integración documental, las capacidades funcionales esperadas y la ambición futura hacia un Gemelo Digital operacional.

Por este motivo, se recomienda estructurar el proyecto en dos grandes etapas:

1. **Etapa 1: Definición técnica, alcance, estándar BIM y estimación técnico-económica.**
    
2. **Etapa 2: Desarrollo de la plataforma BIM / Gemelo Digital según alcance validado.**

# 8. Principio Técnico Clave: No Usar Nube de Puntos Raw en Web
Uno de los principales lineamientos técnicos definidos es que **no se recomienda cargar directamente nubes de puntos pesadas dentro de una aplicación web operacional**.
La nube de puntos debe usarse como insumo de referencia para construir objetos 3D/BIM optimizados.

## Estrategia recomendada
1. Recibir nube de puntos o levantamientos 3D.
2. Usarlos como referencia geométrica.
3. Convertir la información en objetos BIM / 3D estructurados.
4. Optimizar geometrías.
5. Aplicar LOD — Level of Detail.
6. Cargar progresivamente activos en el visor.
7. Usar streaming o carga parcial cuando corresponda.
8. Separar geometría visual de metadata documental y operacional.

## Razón técnica
Cargar nube de puntos directamente puede generar:
- alto consumo de memoria,
- mala experiencia de usuario,
- lentitud en navegador,
- dependencia fuerte de GPU,
- tráfico de red elevado,
- problemas de escalabilidad,
- dificultad de interacción por activo,
- baja eficiencia para plataformas web.

## Mensaje para propuesta

> La nube de puntos será considerada como insumo técnico de referencia, no como formato operativo principal de navegación web. La solución se basará en objetos 3D/BIM optimizados, estructurados por activo y preparados para visualización eficiente.

El mayor riesgo técnico-comercial del proyecto es que el cliente pueda pasar de una expectativa inicial de “visualización” hacia una expectativa de “modelo base de ingeniería”.

Esto cambia completamente:

- levantamiento requerido,
- modelamiento,
- QA/QC,
- responsabilidad técnica,
- entregables,
- y criterios de aceptación.

Por eso, la propuesta debe definir niveles.

# 10. Matriz de Niveles BIM / Uso del Modelo

|Nivel|Nombre sugerido|Uso principal|Precisión esperada|Información asociada|Implicancia comercial|
|---|---|---|---|---|---|
|Nivel 1|Modelo Visual Referencial|Navegación, presentación y entendimiento espacial|Baja / media|Nombre básico, área, tipo|Menor costo y menor plazo|
|Nivel 2|Modelo Operacional por Activo|Identificación de activos y consulta documental|Media|Código, área, sistema, documentación|Recomendado para primera fase funcional|
|Nivel 3|Modelo Técnico Coordinado|Revisión de interferencias, soporte técnico, planos referenciales|Media / alta|Metadata técnica ampliada|Requiere mayor validación|
|Nivel 4|Modelo As-Built de Ingeniería|Mediciones, planos técnicos, proyectos menores|Alta|Información técnica completa|Mayor costo, requiere levantamiento especializado|
|Nivel 5|Gemelo Digital Operacional|Monitoreo, datos vivos, analítica, mantenimiento predictivo|Variable + integración OT|Tags, sensores, KPIs, eventos|Requiere integración OT/IT|

## Recomendación ASTAY

Para el caso actual, se recomienda posicionar la primera implementación como:

# Nivel 2 — Modelo Operacional por Activo

Con posibilidad de evolución hacia Nivel 3, Nivel 4 o Nivel 5, según presupuesto, información disponible y requerimientos del cliente.

# 11. Concepto de Plataforma Propuesta

## Nombre de trabajo

# GemeloBIM

## Portal Visual BIM para Gestión Documental de Activos Industriales

## Concepto

GemeloBIM es una plataforma visual que permite representar digitalmente una planta industrial, navegar sus áreas, identificar activos y acceder a documentación contextual asociada, utilizando un modelo 3D/BIM como interfaz operacional.

La plataforma actúa como una capa visual sobre la información técnica del cliente, conectando activos físicos con documentos, metadata, sistemas y, en etapas posteriores, datos operacionales.

# 19. Riesgos Identificados
## Riesgo 1 — Alcance abierto
El proyecto aún puede variar desde un visualizador BIM hasta una plataforma de ingeniería o Gemelo Digital.

## Riesgo 2 — Expectativa de precisión
El cliente podría esperar mediciones, planos o soporte de ingeniería sin haber definido precisión BIM.

## Riesgo 3 — Información incompleta
Algunos equipos podrían no tener documentación as-built, manuales o metadata suficiente.

## Riesgo 4 — Peso computacional
Nubes de puntos, modelos pesados y geometrías sin optimizar pueden afectar performance web.

## Riesgo 5 — Dependencia documental
La calidad de la plataforma dependerá del orden y metadata de SharePoint.

## Riesgo 6 — Dependencia TI
Azure, Active Directory, VPN, permisos, seguridad y despliegue pueden impactar plazos.

## Riesgo 7 — Dependencia de terceros
El escaneo láser o levantamiento adicional puede requerir proveedores especializados.

## Riesgo 8 — Escalamiento funcional
El cliente podría solicitar datos en vivo, KPIs, alarmas o analítica antes de cerrar la primera fase.

# 28. Texto Base para Justificar la Etapa 1

> La ejecución de una etapa previa de Discovery Técnico es necesaria debido a que actualmente existen múltiples variables abiertas que impactan directamente en el esfuerzo, costo y plazo del proyecto. Entre ellas se encuentran el nivel de detalle BIM requerido, la precisión geométrica esperada, la cobertura de planta, la calidad de la información existente, la disponibilidad de nubes de puntos, la estructura documental en SharePoint, los requerimientos de integración TI/OT y el uso esperado del modelo.
> 
> Sin esta definición, existe el riesgo de subestimar el alcance o comprometer entregables que podrían corresponder a niveles distintos de madurez BIM, desde una representación visual hasta un modelo as-built de ingeniería o un Gemelo Digital operacional.

---

# 29. Texto Base para Diferenciar Visual BIM vs Ingeniería

> Es importante diferenciar entre un modelo visual-operacional y un modelo as-built de ingeniería. Un modelo visual-operacional permite navegar la planta, identificar activos y acceder a información contextual; mientras que un modelo de ingeniería requiere niveles superiores de precisión, validación por disciplina, control de tolerancias, trazabilidad geométrica y capacidad formal para mediciones o generación de planos.
> 
> La definición de este nivel es crítica para establecer correctamente el alcance contractual, los entregables, el esfuerzo requerido y los criterios de aceptación.

---

# 30. Texto Base para Nube de Puntos

> Las nubes de puntos constituyen una fuente de referencia relevante para el modelamiento de planta; sin embargo, no se recomienda utilizarlas directamente como formato principal de navegación web debido a su alto peso computacional y limitaciones de performance. La estrategia recomendada consiste en utilizar la nube de puntos como insumo técnico para generar objetos BIM/3D optimizados, organizados por activo y preparados para visualización eficiente mediante niveles de detalle.

---

# 31. Texto Base para SharePoint

> SharePoint será considerado como el repositorio documental corporativo del cliente. La plataforma propuesta no reemplaza dicho repositorio, sino que opera como una capa visual de acceso contextual, permitiendo que los usuarios seleccionen un activo dentro del modelo 3D y accedan directamente a manuales, planos, procedimientos, fichas técnicas u otros documentos asociados.

---

# 32. Texto Base para Evolución Futura

> La arquitectura propuesta deberá considerar una evolución progresiva hacia un Gemelo Digital operacional. En etapas posteriores, la plataforma podrá integrarse con sistemas OT como DCS Yokogawa, SCADA, OPC, PI System u otros historiadores industriales, permitiendo visualizar variables operacionales, alarmas, KPIs, eventos y señales de salud de activos directamente sobre el modelo digital de planta.
